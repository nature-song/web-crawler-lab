# 命令手册

> 给"没系统学过命令行"的人看的。每条命令都写了**它在干嘛**和**成功是什么样**。
> 遇到 `PS D:\userfiles\desktop\网络系统实践>` 这种开头，表示当前在项目目录里，可以直接执行下面的命令。

---

## 0. 先理解终端

打开 VSCode，按 `` Ctrl+` ``（反引号，Tab 键上面那个）打开终端，或者在项目文件夹里右键 → "在终端中打开"。

终端就是个"用打字代替点鼠标"的窗口：

- 打一条命令，回车，它执行完把结果打印出来；
- `↑` / `↓` 翻之前打过的命令（不用重新敲）；
- 输一半按 `Tab` 自动补全文件名；
- 卡住了按 `Ctrl+C` 中断。

命令前面的 `PS D:\...>` 叫"提示符"，告诉你现在在哪个目录。

## 1. 文件和目录

| 命令 | 在干嘛 | 成功的样子 |
|---|---|---|
| `cd D:\userfiles\desktop\网络系统实践` | 切换到项目目录 | 提示符变成 `PS D:\userfiles\desktop\网络系统实践>` |
| `cd ..` | 回到上一级目录 | 提示符路径少一节 |
| `ls` | 列出当前目录的文件 | 打印一串文件名和大小 |
| `pwd` | 显示当前所在目录 | 打印一行路径 |

> `ls` 是 PowerShell 里 `Get-ChildItem` 的简写，两个都能用。

## 2. 虚拟环境

| 命令 | 在干嘛 |
|---|---|
| `.\.venv\Scripts\Activate.ps1` | 激活虚拟环境。**只影响当前这个终端窗口**，关掉就失效 |
| `deactivate` | 退出虚拟环境 |

成功标志：命令行最前面多出 `(.venv)`，像这样：

```
(.venv) PS D:\userfiles\desktop\网络系统实践>
```

看不到 `(.venv)` 就说明没激活，这时敲 `python` 用的是系统里的 Python 3.9，会报"找不到 requests"。

**不想激活也可以**，把 `python` 换成完整路径：

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

效果完全一样，只是多打几个字。

**报错"禁止运行脚本"**：执行一次下面这句，然后重新激活。

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

## 3. 安装依赖

| 命令 | 在干嘛 |
|---|---|
| `python -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple` | 按清单安装第三方包，`-i` 后面是国内镜像源（快很多） |
| `python -m pip list` | 看当前环境装了哪些包 |

`python -m pip` 的意思是"用 python 去运行 pip 这个模块"，比直接写 `pip` 更保险——能保证装到当前这个解释器里，而不是别的地方。

## 4. 跑测试

| 命令 | 在干嘛 |
|---|---|
| `python -m pytest -q` | 跑全部测试，`-q` = 只打印结果，不打印每个用例名 |
| `python -m pytest -v` | 跑全部测试，每个用例一行，能看到 `PASSED` / `FAILED` |
| `python -m pytest tests/test_robots.py -v` | 只跑 `tests/test_robots.py` 这个文件 |
| `python -m pytest tests/test_robots.py::test_wildcard_and_anchor -v` | 只跑这一个函数 |
| `python -m pytest -x` | 遇到第一个失败就停下，方便先修最前面的问题 |

**输出怎么读**：

```
......................................................          [100%]
54 passed in 0.37s
```

- 每个点 = 一个测试通过；`F` = 失败；`E` = 代码报错（不是断言失败，是运行时就炸了）。
- `54 passed` = 54 个用例全过，说明当前代码是好的。
- 如果失败，会打印 `FAILED tests/test_x.py::test_y - AssertionError`，下面还有 `assert 左边 == 右边` 的具体值，按提示改。

## 5. Git

| 命令 | 在干嘛 |
|---|---|
| `git status` | 看哪些文件改了、哪些还没提交 |
| `git add -A` | 把所有改动放进"待提交区" |
| `git commit -m "feat: 说明"` | 存一个本地快照 |
| `git push` | 推送到 GitHub |
| `git log --oneline -5` | 看最近 5 次提交 |
| `git diff` | 看还没 `add` 的改动内容 |

提交信息前缀：`feat:` 新功能、`fix:` 修 bug、`docs:` 文档、`test:` 测试、`chore:` 杂项。

## 6. 常见报错

| 报错 | 原因 | 怎么办 |
|---|---|---|
| `'python' 不是内部或外部命令` | 没装 Python 或没配 PATH | 用 `py -3.14` 或 `.\.venv\Scripts\python.exe` |
| `ModuleNotFoundError: No module named 'requests'` | 装的包和跑的解释器不是同一个 | 先激活 `.venv`，或用 `.venv\Scripts\python.exe` |
| `无法加载文件 Activate.ps1，因为在此系统上禁止运行脚本` | PowerShell 执行策略 | 见第 2 节最后一行 |
| `no tests ran` | 目录不对（不在项目根目录）或文件名不是 `test_*.py` | `cd` 到项目根目录再跑 |
| `git push` 提示 `rejected` | 远端有你本地没有的提交 | 先 `git pull` 再 `git push` |
| 中文显示成乱码 | PowerShell 编码 | 一般不影响功能；看文件请用 VSCode 打开 |

## 7. 一句话总结

- **`cd`** 去哪儿，**`python -m pytest`** 验代码，**`git add/commit/push`** 存档。
- 命令记不住不用背，用的时候翻这张表，或者直接问我。
- 每次我让你跑命令，都会说明这句话在干什么、成功应该看到什么。

## 3. 缺陷与不一致清单

### 3.1 本轮已修（都有测试或代码可查）

| # | 问题 | 影响 | 处置 |
|---|---|---|---|
| 1 | `RobotsCache.delay_for()` 写好了却没人调用 | robots 里的 `Crawl-delay` 形同虚设，仍按界面间隔抓 | engine 取 `max(界面间隔, Crawl-delay)` 后写入限速器 |
| 2 | 界面有"下载 PDF"勾选框，代码里没有任何下载实现 | 用户勾了没反应，属于欺骗性 UI | 删除该选项与两个配置字段，PDF 下载列入 v2 |
| 3 | `crawl_log` 表建了但从未写入 | 死表，日志只存在于文件 | 改为记录 start / finish / fetch_error 三类关键事件 |
| 4 | `parser` 用 `soup.get_text()[:3000]` 找日期 | 大页面会先把整页拼成字符串再切，白白吃内存 | 改成流式累计到 3000 字就停 |
| 5 | 导出 CSV 没有异常处理 | 文件被 Excel 占用时异常抛进 Tk 回调 | 捕获 `OSError` 并弹窗提示 |
| 6 | 重跑同一批 URL 时界面 "成功 0"、表格空白 | 看起来像程序坏了 | 重复计入"去重"，结束后以数据库为准刷新表格，另加"清空结果"按钮 |
| 7 | 统计快照会覆盖去重计数 | 数字对不上 | 快照只补 `queued`，不再改 `dup` |
| 8 | 统计行与表格列溢出窗口 | 右侧内容被裁掉 | 统计改两行、列宽自适应 + 横向滚动条、日志区收窄 |
| 9 | 静态检查有 9 个告警 | 工程质量基线不达标 | 全部修掉，新增 `pyproject.toml` 固化规则 |

### 3.2 已知未修（v2 处理）

| # | 问题 | 严重度 | 说明 |
|---|---|---|---|
| 1 | 没有"每域名并发上限" | 中 | 4 个 worker 可能同时打同一个站，间隔靠限速器串行化，但并发度未被约束 |
| 2 | robots 缓存只在内存，进程重启就重抓 | 低 | 可落 SQLite |
| 3 | 无内容级去重（不同 URL 同内容） | 低 | 只有 URL 级去重 |
| 4 | 日志无级别过滤、无搜索 | 低 | 长跑后翻日志很痛苦 |
| 5 | 无任务历史记录 | 中 | 每次运行互相覆盖统计，看不到"上次跑了什么" |
| 6 | 时间字段启发式偏宽 | 中 | 已实测：python.org 首页日期来自新闻列表的 `<time>`，不是页面发布时间 |
| 7 | `max_pages` 是软上限 | 低 | 已把在飞任务计入，但仍可能因并发略超 1 页 |
| 8 | 关闭窗口时 join(5s) 有阻塞感 | 低 | 极端情况界面会顿一下 |

## 5. 为什么它现在看起来"简陋"

不是代码烂，是**功能深度和打磨度不够**，具体体现在五个方面：

1. **只有最小闭环**：能抓、能存、能看，但没有"筛选、排序、重抓、续爬、下载"这些真正用起来才会要的功能。
2. **没有"空状态"和反馈**：第一次打开界面，日志是空的、进度是 0，用户不知道下一步该点哪里。
3. **视觉是默认主题**：Tkinter 原生控件，看起来像 2010 年的软件；没有配色、图标、留白设计。
4. **数据没有"洞察"**：只有一张表，没有站点分布、时间分布、字段完整率这些能体现"我做了分析"的图。
5. **工程化缺失**：没有配置持久化、没有打包、没有 CI、没有任务历史——这些是"作品"和"作业"的分界线。

## 6. v2 路线图（建议按此顺序）

### 批 1：地基加固（1 天）

| 项 | 验收 |
|---|---|
| 参数持久化（关掉再开还在） | 重启后种子/策略/间隔保持上次的值 |
| 每域名并发上限 | 同一站点同时最多 2 个请求，可从日志验证 |
| 任务历史表（`runs`） | 界面能看到"本次/上次"统计对比 |
| CLI 测试 | `cli.py` 覆盖率 > 0，参数解析有测试 |

### 批 2：功能深度（2–3 天）

| 项 | 验收 |
|---|---|
| 结果筛选 + 排序 + 分页 | 按站点下拉筛选、按时间排序、5000 行不卡 |
| 断点续爬 | 关掉程序再启动，可继续上次队列 |
| PDF 下载（带大小上限） | 勾选后文件落在 `data/pdf/`，`pdf_links` 记路径 |
| Excel 导出（openpyxl） | 列宽自适应、首行冻结 |
| 内容去重（正文哈希） | 同内容不同 URL 只留一条 |

### 批 3：体验打磨（2 天）

| 项 | 验收 |
|---|---|
| 主题（ttkbootstrap 或自绘样式） | 深色/浅色可切，不再是系统默认灰 |
| 进度 ETA + 实时速率 | 显示"预计还需 2 分 10 秒" |
| 日志级别过滤/搜索/导出 | 只看 WARN、按关键词过滤 |
| 空状态引导 | 首次打开有"三步开始"提示 |
| 打包 exe | 双击可运行，无控制台窗口 |

### 批 4：展示与研究（2 天）

| 项 | 验收 |
|---|---|
| 内置本地测试站点（一键启动） | 断网也能完整演示 |
| 策略对比实验模式 | 一键跑 BFS/DFS/最佳优先并生成对比表 |
| 内嵌统计图（站点分布/字段完整率/速率曲线） | 报告里能直接用 |
| 一键导出实验报告数据（CSV + 图） | 第 4 周做实验时直接产出素材 |

## 7. 质量基线（每次改动都要满足）

1. `python -m pytest -q` 全绿，新增功能必须带测试；
2. `python -m ruff check crawler ui tests run.py` 零错误；
3. 覆盖率不低于当前 88%（新增代码要有覆盖）；
4. 改完必须真跑一次（界面 + 命令行各一遍），不能只看代码；
5. 文档三处同步：README 状态表、AGENTS 进度、本文差距清单。

---

## 8. 需要你拍板的三件事

1. **界面走哪条路**：继续 Tkinter + 美化（成本低、稳），还是换成浏览器前端（好看、但多一层服务）？
2. **v2 优先级**：批 2 的五个功能里，你最想先要哪两个？（我建议"筛选排序"+"断点续爬"，因为它们直接支撑报告里的实验对比）
3. **演示形态**：现场跑本地站点，还是提前录屏 + 现场只演示缓存数据？（后者更稳，但"实时抓取"的说服力会弱一点）
